## 6. Successes and strengths

1. **The user journey is complete without collapsing authority boundaries.** Acquisition is inert; personal
   setup requires explicit IDs or one human confirmation; workspace selection remains independent of
   deliverable targets; handoff is only `prepared`; WPM never claims process, authentication, session, or
   receiving-agent acceptance.

2. **The six-skill family is exact, portable, and independently discoverable.** `wpm-create-package` stays
   personal, while `wpm-author`, `wpm-author-bundle`, `wpm-author-recipe`, `wpm-author-skill`, and
   `wpm-review-package` stay workspace-scoped. Exact package bytes support both native client layouts without
   repository-relative resources.

3. **Authoring state remains outside the deliverable.** Personal setup state, workspace client integration,
   front doors, handoff receipt, shared Backlog, six WPM skills, bundle-contribution records, task definitions,
   and task provenance are excluded from canonical `wip/`, tar, Git, and conditional ZIP outputs.

4. **Predictable failure is no-write; unforeseen failure is truthful.** The implementation consistently
   separates complete preflight from typed ordered partial progress. Retry authority is bound to exact
   operation-owned evidence, not a generic rollback, resume, transaction, or repair promise.

5. **Template-defined work stays declarative and append-only.** The final design supports producer-scoped
   identity, closed WPM context, stable mandatory references, aggregate validation, deep iterative graph
   handling, concrete bundle scoping, actual Backlog IDs, and exact provenance without replacing mandatory
   work or reconstructing history.

6. **Human task state is protected.** Create/enable reconciliation matches machine-owned identity and
   definition while preserving IDs, status, checked criteria, notes, extra metadata, and unrelated labels.
   Source/default changes after recording do not rewrite already materialised work.

7. **Independent review remained load-bearing.** It found authority, ownership, source-binding, terminal
   safety, platform, path confinement, Backlog argv, graph scale, inactive-inventory, race, retry, and final
   postcondition defects that focused implementation bands alone had not closed.

8. **Architecture refined without scope drift.** Concrete operations use bounded, operation-specific immutable
   plans rather than forcing the generic lifecycle sketch into a transaction framework. The pure-core,
   ports-and-adapters, four-port, thin-builder/fat-agent, and SDLC-agnostic principles remain intact.

## 7. Challenges and growth areas

1. **Exact authority and ownership rules repeatedly arrived through review.** Client selection, path identity,
   skill bytes, receipt/state canonicality, legacy recognition, prepared-state replay, task provenance, and
   inactive inventory each exposed a place where “looks right” was weaker than “is authorized.” Future work
   should write the exact ownership proof and hostile-state table before the first implementation pass.

2. **The supported-host behavioral layer is externally fragile.** Claude Code reached deterministic native
   discovery but expired OAuth stopped inference; later Codex probes encountered quota and `bwrap` execution
   boundaries. Correct Course appropriately consolidated live Claude parity at the exact-final gate, but final
   handoff cannot claim full two-host behavioral parity until an authorized fresh Claude session runs.

3. **The full regression became expensive.** The stable suite grew by 619 tests, and TASK-127's final full run
   took 1,852.12 seconds. Cold install dependency timeouts and a quadratic Backlog verification seam were real
   failures found late. Continue focused bands while a diff moves, then run one policy-owned stable full gate;
   treat algorithmic scale and nested timeout budgets as design inputs.

4. **Disposable-tool isolation needs an explicit working-directory guard.** TASK-116/TASK-120 records include
   wrong-cwd Backlog probes that touched repository Backlog state before exact recovery. Other deviations
   included ENOSPC cache pressure, sandbox restrictions, and a shell-quoting mistake that briefly launched an
   unintended test process. A disposable probe should assert its absolute root and repository non-membership
   before any mutating command.

5. **Tracker closure lagged executable closure.** All Epic 2 and Epic 3 stories were done while their epic keys
   remained `in-progress`, and the comment/YAML timestamps disagreed. Workflow-owned status synchronization
   belongs in the same evidence-only closure step as the retrospective.

## 8. Cross-story insights

- **Selection, detection, delivery targets, and authorization are four independent facts.** Detection may
  inform a chooser, but only an explicit ID or human confirmation authorizes setup, and neither selects
  deliverable targets.
- **One authoritative snapshot must drive every later effect.** Re-reading templates, package sources,
  Backlog records, or user front doors after mutation begins creates mixed-revision and overwrite risks.
- **Durable records should be narrow and operation-owned.** Integration state, handoff receipt, personal setup
  state, and bundle-contribution state solve distinct proof problems and should not become one generic state or
  reconstruction database.
- **Exact packaging and non-leakage are paired claims.** A skill is not complete merely because it appears in
  the archive; it must also resolve after source deletion and remain absent from every generated deliverable.
- **Backlog IDs are results, never predictions.** Dependency materialisation must consume actual returned IDs,
  then re-read an exact postcondition before claiming prepared or complete state.
- **Read-only evidence still requires adversarial design.** Fresh copies, pre-marker snapshots, source-Git
  isolation, no-follow path inspection, inert terminal output, and structural capability exclusion prevent
  vacuous “no mutation” or “fresh build” claims.

## 12. Key takeaways

1. Keep authoring selection, deliverable targets, detection, and release authority separate at every surface.
2. Bind package bytes, durable state, task identity, dependencies, and final claims to one immutable operation
   snapshot and an exact postcondition.
3. Treat source-free portability and generated-deliverable non-leakage as inseparable acceptance evidence.
4. Preserve human-owned task state and never infer historical work from a current template or default.
5. Use independent adversarial review for authority, path, ownership, partial-write, graph, and external-host
   seams; the closed findings show it is a correctness mechanism, not ceremony.
6. Complete the exact-final cold and authenticated Claude gates before claiming final handoff, while keeping
   public distribution explicitly inactive until separate human authorization.
