## Story
As `wpm build` and `wpm project validate`, I need to pin every vendored third-party artifact (discipline
skills, Ralph loop runners) to its source + resolved version + a content fingerprint in a `wpm.lock`, and to
verify on build that the vendored content has not drifted from its pinned fingerprint — so a silently-modified
vendored skill cannot ride into a package unnoticed (doc 08; the `--frozen-lockfile` discipline).

## Acceptance criteria (the contract)
1. Each vendored third-party artifact is pinned to a recorded source, resolved version, and content
   fingerprint (doc 08/13).
2. Verification passes when vendored content matches its pinned fingerprint and fails when the content has
   drifted.
3. The recorded pins are sufficient to determine later exactly which version of each artifact was bundled and
   from where.

## Design — `src/core/services/integrity.ts` (PURE; boundary rule applies)
- **`node:crypto` is allowed in core** — pure hashing, NOT on the task-5 forbidden list (which forbids only
  `node:fs`/`node:fs/promises`/`node:os`/`node:child_process`/commander/execa/omelette). `biome check` passes.
- **A vendored artifact is a FILE TREE**: `interface VendoredArtifact { name: string; source: string;
  version: string; files: readonly VendoredFile[] }`; `VendoredFile = { path: string; content: string }`
  (the operation read these via the FS port and supplies them as data). `source` is a string rich enough for
  AC#3 — e.g. `"snarktank/ralph@v1.2"` or `"git+https://…#<ref>"` (a free-form provenance string; keep it a
  string, the author/operation forms it).
- **Content fingerprint — `hashArtifactFiles(files): string`** (AC#1): a deterministic, ORDER-INDEPENDENT
  sha256 over the tree. Sort the files by `path`; for each, feed a CANONICAL encoding into the hash — e.g.
  `update(path)`, a NUL/length separator, `update(content, "utf8")`, a record separator — so the same tree →
  same hash regardless of input order, and BOTH a content change AND a rename alter the hash. Return the hex
  digest, prefixed `sha256:` (self-describing). Use `createHash("sha256")`.
- **Lock entry + lockfile (AC#1, AC#3)**:
  - `interface LockEntry { source: string; version: string; hash: string }`.
  - `interface Lockfile { version: 1; artifacts: Record<string, LockEntry> }` — a small format header
    (`version: 1`) + the map `artifact-name → LockEntry`. (`artifacts` keyed by name; the pins are the
    recoverable record of "which version, from where".)
- **`buildLockfile(artifacts: readonly VendoredArtifact[]): Lockfile`** (AC#1): for each artifact compute
  `hash = hashArtifactFiles(artifact.files)` → entry `{source, version, hash}`. Deterministic; same artifacts
  → deep-equal Lockfile.
- **`verifyLockfile(lock: Lockfile, current: readonly VendoredArtifact[]): VerifyResult`** (AC#2):
  - For each artifact present in BOTH lock and `current`: recompute its hash; if it differs → it DRIFTED.
  - In lock but not in `current` → MISSING. In `current` but not in lock → EXTRA.
  - `interface VerifyResult { ok: boolean; drifted: string[]; missing: string[]; extra: string[] }` — `ok`
    iff `drifted`, `missing`, and `extra` are all empty. (Normal drift/missing/extra are DATA; the operation
    maps to the domain error at task-23.) `ok === true` ⇒ every present artifact matches its pinned hash.
- **Serialize/parse the `wpm.lock` (AC#3)** — MACHINE-MANAGED (regenerated by build, not author-edited), so
  comment-preservation is NOT needed. Use plain YAML via the task-13 leaf for consistency with the project's
  other files:
  - `serializeLockfile(lock: Lockfile): string` → `stringifyYaml(lock)`.
  - `parseLockfile(text: string): Lockfile` → `parseYaml(text)` + minimal structural validation (object,
    `version` number, `artifacts` object of `{source, version, hash}` strings); throw a descriptive Error on a
    genuinely malformed lockfile (an authoring/tamper bug — like render/schema). Round-trip lossless:
    `parseLockfile(serializeLockfile(lock))` deep-equals `lock`.
- **PURE**: import `node:crypto` (allowed) + the task-13 yaml util (`stringifyYaml`/`parseYaml`, a pure leaf)
  — NO `node:fs`/`commander`/`execa`. Boundary clean on `src/core/services/`.
- Export: `hashArtifactFiles`, `buildLockfile`, `verifyLockfile`, `serializeLockfile`, `parseLockfile`,
  `VendoredArtifact`, `VendoredFile`, `LockEntry`, `Lockfile`, `VerifyResult`.

## Tests (`test/unit/services/integrity.test.ts` — pure)
- hash determinism: same tree → same hash; **reordered** files → same hash; a CHANGED content → different
  hash; a RENAMED path (same content) → different hash; empty tree has a stable hash; adding a file changes
  it.
- `buildLockfile`: pins source + version + hash per artifact; deterministic (×2 deep-equal); the hash matches
  `hashArtifactFiles(files)`.
- `verifyLockfile`: PASSES (`ok:true`, empty lists) when content matches; FAILS naming the DRIFTED artifact
  when a file changed; MISSING (in lock, not present); EXTRA (present, not in lock); a mix.
- serialize→parse: `parseLockfile(serializeLockfile(lock))` deep-equals `lock` (all pins preserved — AC#3);
  parse of a malformed lockfile (non-object / missing artifacts / bad entry) throws.
