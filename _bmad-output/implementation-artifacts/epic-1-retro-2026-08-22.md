## 4. Successes and strengths

1. **The inactive boundary stayed truthful end to end.** Package metadata, docs, CLI help, bootstrap
   guidance, candidate state, and both channel assessments all fail closed. A coordinate, registry record,
   or metadata observation cannot silently become authorization or control evidence.

2. **One artifact identity survives the whole journey.** The clean revision produces an exact inspected
   archive; the source checkout is deleted before consumer verification; the installed package, candidate,
   evidence, GitHub assessment, npm assessment, and convergence result all bind back to the same bytes,
   revision, package identity, and digests.

3. **The package and packed-install contracts are generic.** Declared ship-set evolution is checked without
   artifact-type special cases. This is directly reusable when Epic 2 adds WPM-owned authoring skills and
   native front doors.

4. **Read-only means more than “the happy path did not write.”** Structural capability guards exclude
   network, credential, subprocess, publication, tag, owner, trust, and mutation surfaces where they do not
   belong; before/after snapshots prove local and representative external state remains unchanged.

5. **Independent review was load-bearing.** It found and fixed exact-identity gaps, archive traversal/link
   defects, unsafe destination races, Windows invocation/environment issues, open nested schemas, ambiguous
   evidence, noncanonical ordering, and stable-file race weaknesses that focused development and QA bands had
   not fully exposed.

6. **Evidence remained proportional and auditable.** Development and QA used focused bands while each stable
   story revision received one exact reviewer-owned full suite. The suite grew from 1,325 tests at Story 1.1
   closure to 1,473 at Story 1.7 closure without leaking preparation code into `dist`, npm, or generated
   deliverables.

## 5. Challenges and growth areas

1. **Closed input contracts arrived too late in several stories.** Review repeatedly found unknown nested
   fields, malformed digests/revisions, ambiguous duplicates, and contradictory evidence. Future stories
   should define closed schemas, exact identity projections, and canonical aggregate diagnostics as initial
   acceptance-supporting invariants.

2. **Filesystem identity is a cross-cutting security boundary.** Traversal, symbolic/hard links, ordinary-file
   checks, destination replacement, descriptor-versus-path identity, malformed UTF-8, and source realpath
   confinement recurred from packaging through convergence. New effectful adapters should reuse the hardened
   stable-read and path-validation patterns instead of recreating weaker checks.

3. **Platform behavior must be exercised at process boundaries.** Windows npm invocation, `.cmd` shims,
   percent expansion, isolated HOME/USERPROFILE/npm configuration, and Node-before-npm preflight were real
   defects. Epic 2 setup and launch work should keep platform-specific behavior explicit in adapters and
   tests.

4. **The real packed journey is valuable but heavy.** A concurrent TASK-113 integration run hit one bounded
   child-process timeout; isolated and later final reruns passed unchanged. Keep pure contract coverage broad,
   run the real packed journey at the smallest meaningful integration band, and reserve the exact full suite
   for the stable reviewer diff.

5. **Closure records should derive metrics from one source.** The TASK-110 severity-count mismatch is
   harmless to product correctness but avoidable process noise. Future story closure should reconcile story,
   QA, review, and Backlog summary counts before marking the record final.

## 6. Key insights and learnings

- **Availability, identity, control, trust, and authorization are independent facts.** None may be inferred
  from another, even when external state appears compatible.
- **Exactness includes semantic evidence and raw bytes.** File names, metadata, or a single digest are not a
  sufficient candidate binding when later channel decisions depend on the record.
- **Compatibility needs an explicit forward-only vocabulary.** Matching, ready, resumable, complete, blocked,
  and conflicting states prevent destructive “repair” advice such as overwrite, version reuse, rollback, or
  automatic retagging.
- **Determinism is observable behavior.** Closed schemas, canonical ordering, aggregate diagnostics, and
  repeated-byte equality make assessments auditable and safely composable.
- **No-write claims need both architectural absence and runtime evidence.** Capability guards and state
  snapshots reinforce one another.
- **Independent adversarial review should remain a required seam for authority, filesystem, platform, and
  partial-mutation work.** The severity and breadth of closed findings justify the discipline.
