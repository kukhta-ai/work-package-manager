WPM Agent Setup and Authoring Handoff — UX Validation

epics-authoring-agent-onboarding.md · Epic 2 · 2026-08-20T20:44:04Z

The product direction is sound, but the proposed interaction is too administrative. Adapter discovery, detection, installation, update, migration, ownership, and retained state should sit behind one setup intent.

The happy path is one agent-aware setup, one workspace creation, and one fresh-workspace handoff. Explicit consent exists only where personal-scope writes require it.

Recommended experience

  1. The current agent invokes one setup action with its own explicit client ID; it includes another ID only when the user asked for that client too.
  2. WPM preflights all selected destinations, then reconciles only wpm-create-package.
  3. WPM reports configured clients, applicable reload advice, and one exact resume action.
  4. The bootstrap creates the workspace and hands off to a fresh agent rooted there.
  5. The fresh agent verifies the complete backlog and claims or resumes work.

Direct human fallback: without IDs, show Codex and Claude Code once, annotate detection, allow one or both, and ask for one confirmation.
